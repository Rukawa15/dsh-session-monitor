# DSH 跨会话信使 (dsh-session-relay)

把当前会话作为「调度台」：用户在这里口述消息，信使到 DSH 界面里的**另一个会话**代发，
再把对方的回复原样带回。发送走 GUI 自动化，读取回复走会话文件（秒级、结构化）。

脚本位于本插件包根目录 `scripts/monitor.py`（本技能目录的 `../../scripts/monitor.py`，
开发目录 `D:\dsh-session-moniter\scripts\monitor.py`）。

## 固定流程（严格按序执行）

### 第 1 步：定位目标会话（只读）

```
python <包根>/scripts/monitor.py board --json
```
按用户的描述匹配 `title`（任务标题），得到目标会话的 短ID（id 前 8 位）与标题。
匹配到多个候选时，列出候选让用户选，不要猜。

### 第 2 步：GUI 定位与确认（写操作前的安全闸）

1. `list_windows` 找标题含 `DeepSeek Harness` 的窗口（不主动 activate）
2. `accessibility_tree` 读取侧边栏：在 Tree 中找 name 含目标会话标题关键词的
   `TreeItem`（会话行）。找不到时：`scroll` 侧边栏或展开其工作区分组再读
3. **向用户复述并反问确认**（固定话术，使用敬称）：

   ```
   即将把以下消息发送到会话「<标题>」（<短ID>）：
   <消息原文>
   请您确认是否发送。
   另外：需要我在该任务结束后把结果反馈给您吗？
   ```

   用户明确同意后才进入第 3 步；用户没同意绝不发送。
   对「是否回传」的处理：
   - 用户要求回传 → 执行第 4 步（wait 等待并转发回复）
   - 用户不需要 → 发送后即完成，告知用户可随时说「看下 XX 会话进度」自查
   - 预计任务很长（如编译/长任务）→ 告知用户等待可能较久，由用户选择
     现在等还是稍后再查

### 第 3 步：发送（实测经验, 2026-10-29 端到端验证通过）

1. `click(elementId, dispatch="background")` 点击目标会话行切换过去——
   UIA SelectionItem 后台生效，**不移动鼠标不抢焦点**
2. 验证切换成功：find 目标会话历史里的特征文本，或看窗口标题/面包屑已变
3. 定位输入框（Edit，名称含「发消息或创建任务」）
4. **不要用 set_value**（UIA ValuePattern 对 React 受控输入无效，实测写不进去）。
   正确姿势：`focus(输入框)` → `type_text(method="clipboard")` 剪贴板粘贴
5. `keypress ["enter"]` 发送
6. 验证已送达：`python <包根>/scripts/monitor.py tail <目标短ID> -n 5`，
   看到自己的消息原文出现在对方会话文件里才算成功（比 OCR 可靠）
7. 点击本会话自己的会话行（第 2 步记下的 name）后台切回来

### 第 4 步：等待回复并转发（只读，阻塞）

```
python <包根>/scripts/monitor.py wait <目标短ID> --timeout 600
```
阻塞直到目标会话该轮结束，打印其 AI 文本回复。然后把回复转发给用户，
使用固定格式（敬称、注明来源）：

```
【来自「<目标会话标题>」（<短ID>）的回复】（等待 N 分 N 秒）
<回复原文>
```

超时则如实报告：目标会话还在跑或消息未触发新轮次，并询问用户
是否稍后再查或改为定时检查。

## 规则

- 一次只代理一条消息；用户要继续对话就重复整个流程
- **与用户对话一律使用敬称「您」**：把对用户称呼的「你」自然替换为「您」，
  在适当的地方替换即可，不刻意堆砌敬辞；技能输出的话术模板已按此规范书写
- 目标会话若正在生成中，新消息可能排队：等待超时后如实说明，不要重发
- 任何一步找不到元素/点击无效，如实报告卡在哪一步，禁止乱点或盲试
- 发送的消息必须与用户确认过的原文一致，不得自行改写
- 本技能只在用户明确要求跨会话传话时使用；不得用于绕过权限或骚扰其他会话
